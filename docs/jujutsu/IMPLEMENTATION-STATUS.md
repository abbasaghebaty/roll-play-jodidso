# وضعیت اجرایی قوانین جوجوتسو

> این سند وضعیت واقعی کد را ثبت می‌کند. «محاسبه مستقل» به معنی اتصال قابلیت به جریان زنده مبارزه نیست.

## خلاصه فعلی

- مستندات موضوعی بررسی‌شده: ۱۱ از ۱۱
- تصمیمات باز ثبت‌شده: ۲۲ مورد (۲۰ مورد قبلی + ۲ مورد ثبت‌شده در این مرحله)
- محاسبات مستقل اضافه‌شده: دفاع مطلق، دفاع رفلکت، جدول خروجی تکنیک نفرین‌شده معکوس
- اتصال جدید به جریان زنده: حل pending دفاع‌های فعلی از مسیر فرمان و Callback به تراکنش اتمیک و شناسه عملیات یکتا متصل شد. دفاع مطلق/رفلکت و Reversal هنوز متصل نیست.
- تغییر schema یا داده شخصیت‌ها/تکنیک‌ها: انجام نشده

## وضعیت به تفکیک حوزه

| حوزه | وضعیت واقعی | محل کد | تست | باقی‌مانده |
|---|---|---|---|---|
| حمله و رنک حمله | حل‌نشده / عدم اتصال | `rules/attack.js` (فرمول قدیمی)، `ranks/attack.js` (فقط جدول) | تست فرمول قدیمی موجود است | تعارض تاس مثبت با اختلاف دو تاس، اتصال رنک به تکنیک، فرمول جدید و ترتیب افکت‌ها |
| دفاع | ناقص | `commands/combat.js` و `engine.resolvePendingDefense()`؛ محاسبات مستقل در `rules/advanced-defense.js` | تست SQLite واقعی برای حل اتمیک pending و جلوگیری از تکرار اضافه شد؛ CI commit جدید هنوز باید بررسی شود | دفاع مطلق/رفلکت به‌دلیل ابهام منبع تاس و تعامل‌ها هنوز به UI/جریان دفاع وصل نیست؛ پرداخت NP و بازتاب نیز باقی است |
| انرژی و NP | حل‌نشده | `rules/attack.js` (فقط فرمول قدیمی) | تست فرمول قدیمی موجود است | فرمول هزینه جدید، گردکردن، برچسب‌های هم‌زمان، افت قدرت و دیباف |

| خودزنی | ناقص/ناسازگار با مشخصات جدید | مسیر قدیمی در `commands/combat.js` | فقط تست محاسبه عمومی قدیمی | فرمول نصف دمیج قرینه، هزینه NP در شکست، استثناها و حملات فیزیکی |
| Summons | حل‌نشده | هنوز ماژول اجرایی ندارد | ندارد | مدل داده، HP، هدف‌گیری، مصرف و نوبت‌های مستقل |
| وضعیت‌های جانبی | حل‌نشده | هنوز ماژول اجرایی ندارد | ندارد | مود، دیباف، اسپم، مسمومیت، کنترل و زمان‌بندی |
| Domain | حل‌نشده | هنوز ماژول اجرایی ندارد | ندارد | فعال‌سازی، حصار، کلش، تخریب و وضعیت پس از قلمرو |
| Anti-Domain | حل‌نشده | هنوز ماژول اجرایی ندارد | ندارد | محدودیت‌های عملیاتی، مدت، شکست و ترتیب اثرها |

## تصمیم‌های فنی محافظتی

1. تاس و فرمول حمله قدیمی تا تعیین تکلیف اختلاف ساختاری با قانون جدید دست‌نخورده می‌ماند.
2. محاسبات جدید در ماژول‌های pure قرار گرفته‌اند و هیچ‌کدام به‌تنهایی وضعیت بازیکن یا D1 را تغییر نمی‌دهند.
3. دفاع مطلق و رفلکت از دفاع d10 فعلی جدا هستند؛ این جداسازی از تغییر ناخواسته رفتار فعلی جلوگیری می‌کند.
4. Reversal فقط جدول صریح مستندات را محاسبه می‌کند؛ نوع تاس، سقف HP و مصرف نوبت حدس زده نشده‌اند.
5. هیچ تغییر schema، داده شخصیت، تکنیک، قدرت، رنک یا جدول احتمال تاس انجام نشده است.

## وضعیت اعتبارسنجی

- تست‌های واحد جدید به `tests/rules.test.mjs` اضافه شده‌اند.
- ابزار GitHub Actions در زمان این ثبت، فقط اجرای قدیمی روی commit مبنای branch را نشان داده است؛ بنابراین نتیجه CI برای commit جدید هنوز تأیید نشده است.
- تست یکپارچه SQLite برای SQL واقعی و تراکنش batch در `tests/atomic-combat.test.mjs` اضافه شده؛ این تست جایگزین اجرای Production روی Cloudflare D1 نیست.\n- وضعیت GitHub Actions برای Commit جدید هنوز باید بررسی شود؛ تا دریافت نتیجه، تست موفق اعلام نمی‌شود.
- این شاخه هنوز Pull Request ندارد و برای ادغام آماده اعلام نمی‌شود.

## نقطه ادامه

گام بعدی: اتمیک‌کردن ثبت حمله، مصرف NP و تغییر نوبت. اتصال دفاع مطلق/رفلکت و Reversal تا تعیین تکلیف ابهام‌های ۷ و ۱۶ در `DECISIONS.md` متوقف می‌ماند. پیش از اتصال حمله و انرژی باید ابهام‌های بخش ۳.۱ و ۳.۴ در `DECISIONS.md` تعیین تکلیف شوند. قابلیت‌های مستقل دیگر بدون وابستگی به این تصمیم‌ها باید جداگانه ادامه یابند.
